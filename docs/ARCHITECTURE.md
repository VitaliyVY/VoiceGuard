# Архітектура VoiceGuard

## Схема обробки

```
 аудіофайл / мікрофон / голосове
            │  audio.load → 16 кГц моно, нормування, аналіз сигналу (смуга, SNR, кліпінг)
            ▼
 ┌──────────────────────────┬──────────────────────────┬──────────────────────────────┐
 │ 1. Детектор підробки (CM)│ 2. Верифікація мовця(ASV)│ 3. Мовлення → текст → зміст   │
 │ WavLM Base+, шари 2–7    │ MFCC + CMVN              │ faster-whisper small (int8)   │
 │ середнє і σ за часом     │ GMM-UBM (256 компонент)  │ scam.py: 10 тактик,           │
 │ логістична регресія      │ MAP-адаптація середніх   │ 9 поєднань, посилання,        │
 │ → P(справжній), поріг θ  │ → LLR, поріг θ_asv       │ номери карток і телефонів     │
 │ + «підозрілість у часі»  │ (лише якщо обрано мовця) │                               │
 └────────────┬─────────────┴────────────┬─────────────┴──────────────┬───────────────┘
              ▼                          ▼                            ▼
          s_voice                    s_speaker                s_content, s_links
              └──────────────► risk.combine ◄─────────────────────────┘
                     R = 1 − Π (1 − wᵢ · sᵢ)
                     w = {voice 0,9; speaker 0,7; content 0,9; links 0,7}
                     R < 0,3 низький · < 0,6 середній · інакше високий
                                   │
                                   ▼
             вердикт, причини, поради  (+ пояснення ШІ — ai.py, Ollama, необов'язково)
                                   │
                                   ▼
                     журнал SQLite (app_data/journal.sqlite)
```

Рішення ухвалюють лише виміряні модулі 1–3. Мовна модель (ai.py) отримує вже готові факти й лише пояснює їх простими словами — вона не впливає на оцінку ризику.

## Модулі пакета `voiceguard`

| Модуль | Відповідальність |
|---|---|
| `audio.py` | читання будь-якого формату (soundfile / ffmpeg), передискретизація до 16 кГц, нормування, енергія кадрів, відкидання тиші |
| `features.py` | власна реалізація STFT, мел- і лінійних банків фільтрів, MFCC, LFCC (0–8 і 0–4 кГц), Δ/ΔΔ, CMVN |
| `channel.py` | моделювання каналів зв'язку через ffmpeg: Opus 32/16/8 кбіт/с, G.711 μ-law 300–3400 Гц, AMR-NB, AMR-WB, GSM, білий шум 20/10 дБ |
| `metrics.py` | EER, minDCF |
| `models.py` | GMM-детектор підробки (дві GMM: справжня мова / підробка), UBM і MAP-адаптація для верифікації |
| `cnn.py` | LightCNN на LFCC — порівняльний нейромережевий детектор |
| `ssl.py` | витяг ознак WavLM Base+ (torchaudio), агрегування шарів |
| `data.py` | протоколи ASVspoof 2019 LA |
| `asr.py` | розпізнавання мовлення faster-whisper (CPU, int8) |
| `scam.py` | аналіз змісту: тактики («родич у біді», «служба безпеки банку», «виплата», терміновість, секретність…), розрізнення прохання і згадки, поєднання тактик, перевірка доменів (офіційні домени, бренди-двійники, підозрілі зони, скорочувачі), номери карток і телефонів |
| `risk.py` | об'єднання сигналів у ризик, причини, поради |
| `ai.py` | пояснення локальною моделлю Ollama (`gemma3:4b`) з потоковим виводом |
| `system.py` | прикладний рівень: `Detector`, `Verifier`, `VoiceGuard.check()`, `check_text()`, журнал |
| `qt_app.py` | десктопний інтерфейс PySide6 (світла й темна теми) |
| `gui.py` | запасний інтерфейс Tkinter |

## Вибір детектора під час запуску

`system.Detector` обирає найкращу наявну модель:

1. `models/cm_ssl_uk.pkl` — WavLM, адаптований до української (пороги з `scripts/uk_calibrate.py`) — **основний**;
2. `models/cm_ssl.pkl` — WavLM, навчений лише на ASVspoof 2019 LA;
3. `models/cm_gmm_lfcc4k_trim_g128_aug-…pkl` — LFCC 0–4 кГц + аугментація каналами, GMM.

Рівні суворості: «м'яка» — поріг EER на dev; «звичайна» / «сувора» — поріг, за якого 10 % / 20 % справжніх записів dev відхиляється.

## Верифікація мовця

* UBM — GMM на 256 компонент, навчена на справжніх записах train ASVspoof (мовці не перетинаються з dev/eval).
* Реєстрація: MFCC + CMVN з 3–5 записів → MAP-адаптація середніх UBM → `app_data/speakers/<ім'я>.npz`.
* Оцінка: усереднене відношення правдоподібностей «модель мовця / UBM»; поріг — точка EER «свій/чужий» на eval.
* Каскад: спроба приймається, лише якщо і детектор, і верифікація «за» (`Verdict.accepted`).

## Формат результату (`system.Verdict`)

| Поле | Зміст |
|---|---|
| `cm_score`, `cm_threshold`, `cm_genuine`, `cm_confidence` | оцінка детектора, поріг, рішення, впевненість 0…1 |
| `asv_score`, `asv_threshold`, `asv_match`, `accepted` | верифікація мовця і каскадне рішення |
| `timeline` | `t`, `confidence`, `speech` — підозрілість у вікнах 3 с з кроком 0,5 с |
| `transcript`, `language` | розпізнані сегменти `{start, end, text}` |
| `content` | знайдені тактики, поєднання, посилання/номери |
| `risk` | `score`, `level`, `kind`, `signals`, `reasons`, `advice` |
| `analysis`, `notes`, `timings`, `seconds` | властивості сигналу, попередження, час кроків |

## Тести

`tests/test_core.py` — 23 юніт-тести:

| Група | Що перевіряється |
|---|---|
| `TestFeatures` (5) | пік спектра на частоті тону, покриття смуги банками фільтрів, Δ лінійної рампи, розмірності LFCC/MFCC, інваріантність кепстра до гучності |
| `TestMetrics` (3) | EER на розділених/перекривних класах і збіг з теорією для гаусіан, minDCF = 0 для ідеальної системи |
| `TestChannel` (5) | μ-law туди-назад, телефонний канал зрізає верхню смугу, SNR шуму, Opus і мобільні кодеки зберігають довжину й смугу |
| `TestScam` (5) | «служба безпеки банку» і «родич у біді» — високий ризик, звичайна розмова — низький, згадка ≠ прохання, фішинговий і офіційний домен |
| `TestAudio` (2) | відкидання тиші, передискретизація зберігає тон |
| `TestModels` (3) | логщільність діагональної GMM = sklearn, GMM-UBM віддає перевагу зареєстрованому мовцю, детектор розділяє класи |

python -m unittest discover -s tests -v
